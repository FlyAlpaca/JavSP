评估基于 2026-10-10 的仓库源码、离线测试、Ruff、sdist/wheel 构建和现有 CI 工作流。
本地环境使用 Python 3.14；Windows 可执行文件和 Docker 镜像未在本地验证。

| 无人值守 CLI | 无效扫描目录会转入交互选目录；成功后仍固定等待 5 秒；翻译请求在模块导入时提前初始化，使配置错误绕过 CLI 诊断。 | 阶段 2，已完成 |

## 阶段 1：本地元数据批量性能

- 为新导入和已有 R18.dev 数据库建立实体 `id` 索引；旧库建索引失败时保留原库供查询。
- 按来源缓存随包发布的分类表，包括不存在的映射表，避免逐片重复读取。
- 验收：SQLite 查询计划使用实体索引；旧库升级后数据不变；分类结果一致，重复处理只加载一次。
- 提交：`28d31e7`。

## 阶段 2：无人值守生命周期

- 非交互模式只接受存在的扫描目录；无效目录立即以错误码退出，不调用输入或选目录界面。
- 非交互成功结束后立即返回退出码；交互模式保持原有选目录和退出等待。
- 翻译模块仅在实际启用时加载；配置错误经过 CLI 校验路径，无终端时不等待输入。
- 验收：目录不存在、路径为文件、未指定目录、配置无效及成功/失败退出均由离线测试覆盖；Ruff 和构建通过。
- 首次提交：`5ca36ff`；配置错误与延迟导入在后续提交补充。

## 阶段 3：发布产物检查

- 在现有 CI 单元测试通过后构建 sdist 和 wheel，检查打包资源是否包含默认配置、分类表和运行时图片。
- 本地构建与资源检查已通过；Python 3.11/3.14 的 CI 结果需要在推送后确认。

## 阶段 4：真实环境回归与后续改动

- 对输出事务保留现有回滚、跨设备、取消和外部修改回归测试。若出现新的失败样本，先增加可重现测试，再改动提交逻辑。
- 在线抓取按站点运行现有 opt-in 集成测试，记录响应错误和耗时后决定是否调整请求复用或超时策略。测试可能更新 `tests/data/` 样本，运行后需检查差异。
- Docker 和 Windows 可执行文件按对应环境验证。缺少环境时单独标注未执行，不以本地单元测试替代。

2026-10-10 对 JavBus 的 `IPX-177` 样本做了只读在线尝试：当前代理连接收到 TLS 错误，取消代理后网络不可达。
因此本地环境尚不能给出站点可用性结论，样本文件没有变化。
