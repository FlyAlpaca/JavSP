# 元数据说明

[返回 README](../README.md) · [使用指南](usage.md) · [元数据说明](metadata.md) · [升级指南](migration.md)

说明当前 2.x 的数据来源、演员名称和图片处理规则；内部匹配算法见[开发指南](development.md)。

## R18.dev 本地数据库

R18.dev 本地库始终启用，无启停开关。以下通用规则可在用户配置中调整：

```yaml
r18dev:
  required_keys: [cover, title]
  normalize_actress_name: true
  respect_source_id: true
```

`required_keys` 指定整理必需的字段；`normalize_actress_name` 控制别名归一；
`respect_source_id` 控制是否采用数据库记录中的正式番号，关闭时保留文件名识别的番号。

旧配置的迁移方式见[升级指南](migration.md#元数据配置迁移)。

首次启动时查询 [R18.dev 公开 Wasabi 转储](https://r18dotdev.s3.eu-west-1.wasabisys.com/?list-type=2&prefix=dumps%2Fr18dotdev_dump_) 并下载导入；本地数据库上次成功导入未满 7 天时，启动会跳过远端更新检查。满 7 天后检查远端，只在转储日期更新或同日对象 ETag 变化时重新导入；检查未发现新转储时，后续启动仍会继续检查。旧版数据库没有导入时间时，以文件修改时间判断；没有 ETag 时会先重新导入一次以记录对象身份。下载使用四连接分片并支持中断续传；范围请求不可靠时回退单连接。库固定保存在**启动工作目录**的 `config/r18dev.sqlite`，Docker 中即 `/app/config/r18dev.sqlite`，与 `-c` 指定的配置文件位置无关。请持久化 `/app/config`，并为下载分片、组装的压缩转储、旧数据库及导入时的临时库预留空间；组装时压缩转储会短时占用约两份空间。

处理影片时先查询本地库。DVD 番号优先精确匹配，再查询仅数字前导零不同的写法；同等级多条命中时，按 `content_id` 字典序升序选第一条。仍未命中时，一次查询所有 CID 候选：保留未补零、五位补零等既有优先级，再尝试本地库实际观测的厂商前缀，例如 `1start00538`、`118ipx00658`、`h_086fsdss00615`。厂商前缀表在导入时生成，旧库启动时一次补建。若 CID 记录带有不一致的 DVD 番号，则不使用该记录。指定完整 CID 时只精确查询，不改写其数字；详细依据见[开发指南](development.md#r18dev-查询与选择规则)。本地未收录、查询失败或缺少必需字段时，该影片失败并保留源文件，普通失败可继续批次。
数据库更新失败时保留可用旧库；首次无有效库且准备失败时终止启动。
元数据查询不访问在线站点；数据库更新、演员映射、模型和图片仍按需联网下载。

## 女优名称与别名

女优名称使用 [Jav Actors Mapping](https://github.com/li-peifeng/Jav-Actors-Mapping) 的 `actor-mapping.xml`，不再使用内置 JSON 表。每次启动都会检查 GitHub 更新：已有有效缓存和匹配的版本元数据时，先通过 HEAD 请求检查 ETag，返回 304 或 ETag 相同则直接复用缓存，不下载 XML；确认版本变化后才下载并校验，再开始整理。服务器不支持 HEAD 时回退条件 GET 检查。缓存或版本元数据缺失、损坏时重新获取。缓存固定保存在**启动工作目录**的 `config/actor-mapping.xml`，Docker 中为 `/app/config/actor-mapping.xml`；版本信息保存在同目录的 `actor-mapping.json`。请持久化 `/app/config`。下载支持 `network.proxy_server` 和环境代理。服务器支持可靠范围请求且提供强 ETag 时，使用 1 MiB 分片、最多四连接下载；连接/读取超时分别为 30/120 秒，网络失败最多尝试三次，并保留分片供同版本续传，远端版本变化时清理旧分片。不支持可靠范围请求时回退单连接。完整下载通过 XML 校验后才替换缓存。更新失败时告警并使用有效旧缓存；首次无法获取映射且没有有效缓存时终止启动。

名称统一展示为 `原名（中文译名）`，例如 `新ありな（新有菜）`；中文优先使用简体，其次使用繁体。中文字段须包含汉字且不含日文假名或重复符号 `々`，日文或纯罗马音占位值不作为中文译名；与原名完全相同的简体字段也不会遮住有效繁体字段。同一日文原名的重复条目中，空值、日文占位及与原名相同的值不会遮住唯一有效译名，例如 `木下ひまり（木下日葵）`；存在多个不同有效译名时保留输入名称。没有中文译名或名称相同时只展示原名，不用模型猜测人名。该格式始终生效；`r18dev.normalize_actress_name` 控制普通 `keyword` 别名是否归到主名，默认开启。关闭时别名仍查表并格式化，但保留抓取到的别名，例如 `橋本ありな（新有菜）`。存在显式 `alias` 子节点译名时，保留的别名采用专属译名；否则采用所属主名的中文名。

中文字段缺失或无效时，从同一原名的 `keyword` 中按字符结构回退。先按通用字符表归一日文异体字、展开前有汉字的 `々`，再用 OpenCC 统一简繁：如 `桜 → 樱`、`嶋 → 岛`、`寧々 → 宁宁`。原名至少保留一个汉字锚点，每段假名对应一个或多个汉字，其他汉字须完整匹配；纯假名、混有拉丁字母或标点的原名不推断。因此 `桜ゆの` 可从 `樱柚乃` 得到中文名；`三澄寧々`、`七嶋舞` 则匹配上游已有的 `三澄宁宁`、`七岛舞`。`神宮寺ナオ` 可匹配 `神宮寺奈緒`，而同条目中的 `松岡芽郁`、`池田充希` 不匹配。

回退会合并同一原名的重复条目及简繁等价候选，只有唯一候选且它在整张表的原名、中文字段、别名中唯一归属该原名时才采用；多种汉字写法或跨演员冲突时保留原名。字符结构匹配是回退推断，无法判断唯一匹配的同姓旧艺名是否就是译名。有效上游中文字段仍优先，多个有效译名冲突时仍保留输入。纯汉字原名已有同名中文字段或简繁等价 keyword 时，通用简繁转换可生成 `彩月七緒（彩月七绪）` 等展示，也需满足唯一归属检查；其他有效中文字段保持上游写法。

完整名称先做精确查表，未匹配时再做字符归一查表。对于 `现名（旧名）` 或半角括号组合，只有括号内外分别唯一匹配到同一演员时才拆解，并保留首个名字作为展示名，不受普通别名归一开关影响；跨演员、未知部件或嵌套括号保持输入。显式的别名专属译名由演员身份确定，允许不同演员具有相同中文名，但同一别名的译名冲突仍保留输入。

启动时另外读取随包发布的[演员补充数据](../javsp/metadata/data/actor-supplement.xml)，用于上游缺失条目及新旧艺名专属译名，出处随数据记录，不在 Python 中维护姓名分支。已有有效上游中文字段及显式别名译名优先，补充数据不写入 GitHub 缓存，也不能替代首次启动所需的有效上游映射。当前补充 `和香なつき（和香夏月）`，以及同属 `藤浦めぐ` 条目的 `めぐり → 惠理`，组合名因此展示为 `めぐり（惠理）`；普通主名仍为 `藤浦めぐ（藤浦惠）`。字符表、补充格式、来源选择及译名差异见[资源说明](../javsp/metadata/data/README.md)。

上游及补充数据均未收录的名称、缺少原名的条目及无法唯一匹配的别名保留抓取名。上游别名覆盖与旧表不同，主名也可能变化。目录、命名模板、NFO 演员和头像引用使用同一份汇总结果，转换后的重复姓名会合并。R18.dev 有头像地址时，直接写入 NFO `actor/thumb`，供媒体中心获取；JavSP 不下载或生成本地演员头像。

绿联显示演员头像需要 NAS 能访问 NFO 中的图片地址，绿联社区的[实测反馈](https://club.ugnas.com/forum.php?mod=viewthread&tid=2144)确认使用 `actor/thumb` 图片 URL 可以下载头像；媒体库需启用“优先读取本地信息”，更新 NFO 后需让媒体中心重新读取元数据；已整理的影片不会自动批量改名或改写 NFO。

## 封面与剧照

默认要求抓取结果包含标题和封面。DMM 封面按原图 CDN、普通大图、缩略图的顺序尝试，并优先使用独立竖版原图生成海报；`folder.jpg` 保留海报尺寸。其他来源仍先尝试高清地址再回退普通地址。剧照单张失败不会阻止其他剧照或影片处理。
